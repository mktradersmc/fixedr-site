# Structure

Every chapter follows the same three-step shape, then names what it replaces:

1. **Problem, named.** A specific failure mode, described as behavior — not as a feature gap.
2. **What actually fixes it.** The underlying requirement, stated before any product appears.
3. **How the platform closes it.** The concrete mechanism (register reference kept as a
   source-only comment, never printed).
4. **What it competes against.** The alternative a prop trader reaches for today, in behavior,
   never by product name.
